# NFR-001 — Quality requirements

**Status:** Proposed v0.1; human review and ASR evidence required.
**Applies to:** [PRD](../product/PRD.md), M0 and the future MVP.
**Evidence today:** None; this is a measurement contract, not a benchmark report.

## Latency and accuracy

Use monotonic timestamps and report p50/p95/p99, sample counts, confidence
intervals where meaningful, hardware, browser, model version, warm/cold state,
network conditions, and exact configuration. Report both overall and per-cohort
results; do not hide poor cohorts in a pooled average.

| ID | Target / definition | Verification |
| --- | --- | --- |
| NFR-L01 | M0 p95 ≤1,000 ms; MVP proposed p95 ≤800 ms from annotated acoustic end of a word to its first **usable** visible aligned feedback | Timestamped audio replay plus instrumented end-to-end UI; report revision/stability delay separately so a fast incorrect guess does not count as useful feedback |
| NFR-L02 | Alignment processing p95 ≤5 ms per incremental update | Benchmark declared passage lengths/update sizes on named reference devices; include repeats, corrections, and ambiguous passages |
| NFR-L03 | Planning budgets: buffering ≤100 ms, network contribution ≤150 ms typical, partial ASR ≤500 ms typical, UI work ≤16 ms | Instrument stages without double-counting overlapping work; “typical” is p50 for research reporting. These budgets are diagnostic, not a substitute for the end-to-end gate |
| NFR-A01 | ≥98% of annotated correctly recited reference-word events accepted correctly on the frozen controlled test set | Correct accepted events / all correctly recited reference-word events; uncertainty counts as not accepted; report by speaker and condition |
| NFR-A02 | ≥95% omission recall and ≥95% substitution recall, reported separately | Correctly detected labelled error events / all labelled events of that type, using a predeclared matching tolerance |
| NFR-A03 | Measure false accusation rate, error precision, false acceptance of incorrect words, and uncertain coverage; numerical limits TBD before model selection | Correct recitation events falsely flagged / correct events; true flagged errors / all flags; incorrect events accepted / all incorrect events; unresolved events / all scored events |
| NFR-A04 | Repeats, corrections, pauses, revisions, and āyah transitions do not corrupt alignment; uncertainty is not a definite mistake | Golden state transitions, adversarial streaming and property tests; correction/scoring window specified before feature implementation |

Do not call M0 fully passed until the human owner approves A03 limits and
reference conditions, and the held-out results meet all agreed gates. Otherwise
report conditional/inconclusive or no-go. The ≥98%/≥95% targets originate in
planning; their practical attainability remains unknown.

## Integrity, reliability, privacy, and security

| ID | Requirement | Verification |
| --- | --- | --- |
| NFR-I01 | Authoritative, licensed, versioned/checksummed text and recordings; immutable display data independent of normalization | Provenance/rights review, import validation, checksum tests and qualified content review |
| NFR-I02 | Stable sūrah/āyah/word IDs and cue timing maps under a declared convention | Boundary/mapping golden fixtures, cue playback review, rejection of mismatched assets |
| NFR-R01 | Denied microphone, disconnect, timeout, model failure, and cancellation are recoverable states without false scoring or leaked capture | Failure-injection and session lifecycle tests; exactly defined recover/retry paths |
| NFR-R02 | Proposed soak target: complete a 30-minute research session without crash, unbounded queue growth, or retained capture after exit | Record memory/queue behavior, errors, and cleanup on reference hardware; confirm duration/resource budgets in ASR-003 |
| NFR-P01 | Explicit microphone action and clear local/remote disclosure; no persistent audio/transcript retention by default | UI, network, log, storage, and provider-terms inspection; remote retention unknown fails the gate |
| NFR-P02 | Saved pilot debugging samples require explicit agreement on purpose/access/deletion date and honored deletion requests; structured research recordings additionally require purpose-specific consent/rights, retention and withdrawal arrangements | Verify pilot sample agreements and deletion across copies; approve the structured research protocol and dataset manifest before research collection/transfer; no private recordings in git |
| NFR-S01 | Protect transport/credentials; validate untrusted input; no sensitive payload logging | Threat model, transport/configuration review, dependency audit and negative tests appropriate to chosen stack |

No availability SLA is claimed before an architecture exists. Define service
availability and recovery targets in an ADR/release ticket if hosted services are
selected.

## Access, compatibility, offline behavior, and cost

| ID | Proposed target or unresolved constraint | Verification / decision gate |
| --- | --- | --- |
| NFR-U01 | WCAG 2.2 AA target; Arabic RTL, keyboard operation, visible focus, accessible names/status, non-color error cues | Automated checks plus manual screen-reader/RTL/zoom review before MVP |
| NFR-C01 | Evaluate desktop Chromium/Firefox/Safari and Android Chrome/iOS Safari; exact supported versions/devices TBD | ASR-007 publishes tested capability matrix; approve support policy before MVP scope is finalized |
| NFR-C02 | Offline inference is a research option, not a promised feature; unavailable network/model must be explained without grading failure | Offline/startup/interrupted-download scenarios; ADR explicitly declares what works offline |
| NFR-C03 | Affordable operation; currency-denominated cost ceiling TBD by human owner before provider selection | ASR-008 reports cost per 10-minute session and at 100/1,000 monthly active users, including usage assumptions, idle compute, transfer, storage, and model download; no claim of affordability without an approved ceiling |

The 30-minute soak and cost-reporting scenarios are proposed operationalizations,
not previously approved product commitments. Device classes, memory/download
limits, accessibility test matrix, and error/cost ceilings must be ratified in
research tickets. Missing thresholds remain visible as open gates.

## Traceability and change control

ASR-001/002 cover accuracy data and scoring; ASR-003/005 cover latency/reliability;
ASR-006 covers constrained decoding and integrity; ASR-007 compatibility/offline;
ASR-008 cost; ASR-009 and SEC-001 privacy/security; ASR-010 records the decision.
[TEST-STRATEGY.md](../testing/TEST-STRATEGY.md) maps these requirements to test types.
Targets may change only through a reviewed PR with measurement evidence and human
approval, never by tuning on the held-out test set and rewriting the gate.
